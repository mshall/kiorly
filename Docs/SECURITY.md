# Security

* **Auth.** Two ways in, same session model. (1) **Kiorex Passport** (implemented 23 Nov 2026, `src/auth/passport.ts`): OIDC authorization code + **PKCE S256** as the public client `kiorly` (redirects `kiorly://auth/callback`; Expo web `<origin>/auth/callback`; scopes `openid profile phone kx kx_org offline_access`; `state` + `nonce` per request, `iss`/`aud`/`nonce`/`exp` of the id_token checked). The browser step uses the system auth session (ASWebAuthenticationSession / Custom Tab / popup on web). The **Passport access token is the bearer** for the product API, which verifies it (JWKS, issuer, audience, `client_id` claim) and maps `sub` to its own staff row (role and tenant come from the product, never from the token; ADR-013). Access tokens live 15 min; the app refreshes through Passport (`refresh_token` grant, rotating, reuse detection server-side) and stores the new refresh token each time. Each product sign-in is its own grant, so refresh tokens are never shared between products. A 403 `PASSPORT_NOT_LINKED` (or 401) from the product's first call leaves nothing stored and shows a plain explanation. (2) **Product login** (dev and the fallback): Clinic `POST /auth/login` (access + rotating refresh token; single-flight refresh in the client), Pharmacy `POST /auth/login` (10 h token, no refresh), Lab `POST /auth/dev-login` (dev only); the demo chips stay in `__DEV__`.
* **Sign-out.** Per product: delete the device record (drops the push token), clear the local session and caches; for Passport sessions also revoke that grant's refresh token (RFC 7009, best effort) and, once no other product session still uses Passport, end the Passport session with **RP-initiated logout** (`end_session_endpoint?id_token_hint=...&post_logout_redirect_uri=kiorly://auth/logout&client_id=kiorly&state=...`), so the browser's Passport cookie is gone and "Sign in with Passport" shows the login again. `id_token_hint` makes Passport skip its "Stay signed in?" prompt. Offline or a dismissed browser never blocks sign-out. Remote sign-out / expiry clears only the local session and does not end Passport.
* **Client registration.** `kiorly` (and the legacy `kiorly-team`, kept for old dev builds) in `kiorex-account/config/idp.json`; staging/production app client and final redirect URIs are NEEDS_HUMAN. Config: `EXPO_PUBLIC_PASSPORT_ISSUER` (default `http://localhost:4400`), `EXPO_PUBLIC_PASSPORT_CLIENT_ID` (default `kiorly`), `EXPO_PUBLIC_PASSPORT=off` hides the button. Clinic's `kiorly-clinic` client is confidential/server-side (web) and not used by the app.
* **Device-bound sessions.** After login the app registers the install (`POST /mobile/devices`); the server returns an opaque device token once (stored hashed), kept in SecureStore (Keychain/Keystore). Every request carries `X-Kiorly-Device(+Token)`; a revoked/unknown device gets 401 `DEVICE_REVOKED` and the app wipes the session.
* **Remote sign-out.** `DELETE /mobile/devices/:id` by the user or an org admin (`/devices` screen). Clinic also revokes the refresh session; Pharmacy/Lab (no refresh) rely on the device guard on the next request.
* **Biometric lock.** `expo-local-authentication` (Face ID/fingerprint, device-credential fallback); locked on cold start and after a configurable grace (0 s / 30 s / 5 min) in background; a full-screen cover hides content. Not available on web.
* **Storage.** Tokens and device tokens: SecureStore (sessionStorage on web, dev only). Preferences and the offline cache/queue: AsyncStorage in the app sandbox (OS data protection); cleared on sign-out. No analytics SDK; no PHI in logs; push templates carry no clinical values (Lab never includes result values).
* **Transport.** HTTPS in staging/production (EAS env vars); localhost HTTP only in dev. `X-Kiorly-Client` identifies the app for entitlement enforcement; it is not a secret.
* **Privacy by role.** Modules come from the server per role; the app hides actions the role cannot do, the server remains the authority (403 => friendly "not allowed").
* **Mock providers.** Push is a mock sender (`MOBILE_PUSH_MODE=mock`): messages are stored as the in-app inbox and the app polls; real Expo push is a go-live task listed in each product's `Docs/NEEDS_HUMAN.md`.
* **Not done / backlog:** encrypt offline queue/cache with a SecureStore key; certificate pinning; jailbreak/root detection; Passport public client; screenshot blocking on Android (`FLAG_SECURE`).
* No tax-authority integration exists or is planned (founder decision).
